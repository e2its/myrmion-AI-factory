# ADR-EVOL-049: Role agents and read-only critics

## Context

Issue #58, axis E of the 2026-09 evolution (#50). The framework's headline model was one agent wearing hats: the same context played PO, UX, architect, developer, reviewer and security. Two structural costs were measured downstream: a reviewer who wrote the code is not a reviewer (the review hat inherited the author's context and blind spots; the review loop was the stickiest phase while producing the least activity; rework stayed near one sixth), and one context carried everything. Splitting phases into agents with their own context and making reviewers read-only adversaries moved both numbers — and blew up token cost once every critic read the whole corpus, which a digest and a per-spawn model policy closed. Measured here before design: no agent roster existed; the six vendored review agents carried no tool matrix (read-only was a sentence in a prompt); the only model table lived in one skill; the review and security hats were named in twelve instruction and skill files. Decision authority delegated by the user on 2026-09-25; this ADR is the branch's plan under EVOL-048.

## Decision

Agent-internal choices (pick + surviving risk):

- **One data home for every class policy.** `rules/agents.md` (template rule; the framework's rules root reads the template) carries in its frontmatter: the **classes** (`phase`, `worker`, `plan-critic`, `work-critic`) with the tools each must have and must never have, a byte budget per agent prompt and a model **family** + effort; the **families** as harness aliases (`writer`, `critic` — a project decision at SETUP Q34, never pinned ids); **size tiers** (files, lines) and the **per-spawn resolution** table (class × surface × tier × round → family + effort — strongest where the risk is highest, stepping down where the diff is small); the **fallback ladder** keyed by the resolved alias (writer classes excluded — an agent that writes never degrades); the **round caps** (one worker↔critic round on a completed diff, two at the plan gate); the **roster** (name → class, phase or surface, the surface globs its digest covers). Changing the model table is a rule-file edit plus a manifest bump, never a code change, and the change carries its measurement window. Rejected: a JSON under `config/` — the policy is law about how the work is reviewed, and its body (the severity bar, the return contracts) belongs in a rule.
- **One reader.** `scripts/gates/agents.py` behind `gate.py agents`: `--validate` (roster parity with the manifest, tools per class present and none of the forbidden ones, model and effort present, prompt bytes within the class budget, every pointer in an agent body resolving, **critic family ≠ writer family** for the surface a critic reviews — refused otherwise —, the ladder keyed only by resolved aliases and never reaching a writer class, every spawn site declaring its policy and every policy having a site — both directions); `--resolve` (per-spawn model + effort from the class, the surface, the size tier and the round); `--fallback` (the next rung for a resolved alias, refused for writers); `--digest` (the slice of law governing the agent's surface, within its class budget — the EVOL-043 digest, so a critic never reads the corpus); `--check-return` (a worker return without its governance block — rules read, laws applied, defect classes adjudicated, sources — or a critic return without file, line, severity, confidence and an executed probe is refused). The validator is a member of the gate profile (no build, no database) and runs in CI.
- **A roster on two axes, harness-enforced.** `.claude/agents/` (delivered from the template tree): one agent per framework phase (`factory-codesign`, `factory-blueprint`, `factory-implement`, `factory-qa`, `factory-devops`), development workers per surface (`factory-dev-backend`, `factory-dev-frontend`, `factory-dev-platform`, `factory-dev-e2e`), a plan critic (`factory-plan-critic`) and four work critics split by concern (`factory-critic-security`, `factory-critic-correctness`, `factory-critic-governance`, `factory-critic-fidelity`). Delegation is by name; agents carry no self-discovery of applicability. Read-only is the harness's tool matrix: a critic definition lists no `Edit`, `Write`, `NotebookEdit`, `Bash` or `Agent`, so an attempted write cannot happen; the orchestrator also hashes the tree before and after a critic run (`gate.py certify --subject tree`) and refuses a run around which the tree moved.
- **The LAW-13 engine stays as the correctness lens's instrument.** The six vendored review agents (Apache-2.0) gain a `tools` matrix and a class (`work-critic`) and run under the correctness lens; the security, governance and fidelity lenses are new critics. Rejected: replacing the engine — its marker, its severity normalisation and its push-gate wiring are proven; the lens model is the class above it, not a rewrite. (A decision the issue left to execution; delegated authority, recorded here.)
- **A severity bar with two limbs.** A finding rises above informational only by naming a concrete path to the deployed product (including any exposure of a credential or a personal datum) or to the machinery that produces or polices the work; on a governance surface the burden inverts — informational is the default and escalation must be justified. Stated once in the rule body, cited by every critic definition.
- **A bounded loop ending in a user adjudication.** One round on a completed diff, two at the plan gate — the measured point of diminishing return; a cure that seeds the next round's findings is the loop's own defect, so the round caps are keys and the end is the user's call, never the agent's own judgement. **No agent ratifies**: RDR, user questions and version-control operations stay in the main session; no subagent commits, no subagent decides.
- **The hats retire.** "REVIEW Hat" and "SEC Hat" (and their glyph forms) leave every instruction, skill and command; their checks are re-homed onto the lenses — the fourteen review checks onto the correctness and governance critics, the SAST protocol onto the security critic — and the swept names enter the retired-vocabulary ratchet so they cannot walk back in.
- **Measurement.** `measure.py` joins each sub-agent to its roster class and reports bytes, citations and model per agent and per round — the shape ships here; the numbers come from an adopting project (#51).

## Consequences

- New: `scripts/gates/agents.py` (lock-step, delivered); `gate.py agents`; `rules/agents.md` (template; SETUP Q34 resolves the two family aliases); fourteen agent definitions under `.context/templates/setup/claude/agents/` mirrored to `.claude/agents/`; the profile member `agents`.
- Changed: the vendored review agents carry `tools` and `class`; the review-checks instruction becomes the lenses' checklist; the build, blueprint, code-review, pr-review, preventive-sweep and applicability skills spawn by name and declare their policy; the retired terms grow.
- `framework_version` 7.5.0 → **8.0.0** (MAJOR — the one-agent-wearing-hats model is replaced; downstream instructions that named a hat no longer resolve; branch `feature/EVOL-049-role-agents`).
- No new LAW. Both `CLAUDE.md` sides: § Core Protocols gains the agents protocol row and the "no agent ratifies" sentence.

## Alternatives considered

Critics on the writers' family with a stronger prompt — rejected: a critic on the author's model inherits the author's blind spots; the separation is the invariant, the aliases are the project's. Unlimited rounds until green — rejected: measured diminishing return and cure-seeded findings. Critics reading the corpus — rejected: the measured cause of the token blow-up.

## Operational Rule

No LAW added. Both `CLAUDE.md` sides: the Core Protocols table gains "Role agents & critics" pointing at `rules/agents.md` and `gate.py agents`; the sentence "no agent ratifies" is universal. Both lock-step sides updated; universal sections and the LAW corpus untouched.
