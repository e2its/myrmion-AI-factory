# Template C: Quality Report

Materialised by `QA --verify {{FEATURE_ID}} [{{INC-N}}]` as a checkbox-driven verification artefact. The verdict is computed, never written by hand (EVOL-076). `python3 scripts/gate.py qa --verdict` approves a report only when:
- every `- [ ]` is `- [x]`;
- no `## Findings` row is at or above `config/quality.json → qa.blocking_severity`;
- every owed item is present.

The completion hook refuses `verdict: APPROVED` otherwise.

**Path is mode-aware:**
- Slice mode (`/qa --verify {{FEATURE_ID}} {{INC-N}}`): `docs/spec/{{FEATURE_ID}}/qa/qa_report_{{INC-N}}_{{timestamp}}.md`. Required for `slicing_strategy: incremental` features.
- Aggregate mode (`/qa --verify {{FEATURE_ID}}`): `docs/spec/{{FEATURE_ID}}/qa/qa_report_final_{{timestamp}}.md`. Sole report for `slicing_strategy: monolithic` features. For incremental features it cross-references slice reports via `aggregates:`.

## Findings

Every finding of this verification, whatever its source (SAST, DAST, the QA scripts, the DC items, the regression suite), one row each. Severity is the closed vocabulary `critical | high | medium | low | info`:
- a tool's own grade is mapped one to one;
- a failing script, a regression or a failing DC item → `critical`;
- a flaky test → `low`.

A row at or above `qa.blocking_severity` blocks approval. An empty table, header only, means no finding.

| ID | Severity | Source | Finding | Evidence |
|----|----------|--------|---------|----------|

## 1. Static Analysis
Results of the independent re-execution of lint/typecheck/SAST.

## 2. Test Execution
Results of the independent re-execution of unit/integration/contract test suites. Include stderr hashes or evidence paths.

## 3. DAST Findings
The ZAP alerts, each a `## Findings` row (High → high, Medium → medium, Low → low, Informational → info). A probe not run says `n/a: <reason>` on its item.

## 4. Defect Prevention Findings
Occurrences of cataloged DC patterns found during QA review. Each finding links to the DC entry in `.claude/rules/defect-prevention.md` and, if actionable, a follow-up task in the backlog.
