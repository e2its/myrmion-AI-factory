# Project Constitution — Index of Project Law

> Index of the project's operational law: one `## [PLAW-NN]` entry per law — a normative sentence, the pointer to its body, its records. Generated by `/SETUP --generate`; technical instructions in English.
> Bodies live in `.claude/rules/` (or the named skill / instruction) under a heading with the same id and the byte-identical sentence. One body per law.
> Change ceremony: the sentence changes only through an ADR reaching `status: accepted` in the same PR (`factory-adr-management` Accept Procedure, `Records:` appended); the body changes through a rule-file edit plus a governance-manifest bump.
> Universal framework law (`[LAW-NN]`) lives in `CLAUDE.md` § Governance Rules, never here; project-minted ids stay in the `PLAW-NN` namespace.

## [PLAW-01] Fundamental Principles (KISS & DRY)
> Every technical decision is the simplest one that meets the current requirement, and every piece of knowledge has one authoritative representation in the system.
Body: `rules/architecture.md` · Records: `ADR-0000`

## [PLAW-02] Stateless Design Policy
> Every service scales horizontally without session affinity: no instance-local state, distributed cache for shared data, idempotency keys on every mutation.
Body: `rules/stateless.md` · Records: `ADR-0000`

## [PLAW-03] Project Mode & Extension Strategy
> The project declares whether it is built from scratch or extends an existing codebase, and existing code is touched only as the declared extension strategy allows.
Body: `rules/project-mode.md` · Records: `ADR-0000`

## [PLAW-04] Code Readability & Maintainability
> Code readability for humans is always prioritised over brevity or optimisation tricks: a function does one thing and a reader grasps its purpose without decoding.
Body: `rules/architecture.md` · Records: `ADR-0000`

## [PLAW-05] Configuration Hardcoding Prohibition
> No configuration value, infrastructure name, endpoint or credential lives in source code; each is externalised to configuration or to the secrets tier matching where it runs.
Body: `rules/configuration.md` · Records: `ADR-0000`

## [PLAW-06] Security by Design
> Security is validated in every feature, never deferred to a sprint: OWASP controls, static analysis gates and default-deny networking apply from the first line.
Body: `rules/security_policy.md` · Records: `ADR-0000`

## [PLAW-07] Privacy & GDPR Compliance
> Privacy is a right, not a feature: data is minimised, purpose-bound, retained for a documented time, classified by sensitivity, and every user right is served.
Body: `rules/privacy.md` · Records: `ADR-0000`

## [PLAW-08] Internationalization Strategy
> The project declares its locale, currency and timezone scope; user-facing strings are never hard-coded and values are stored in canonical form, formatted at presentation.
Body: `rules/i18n.md` · Records: `ADR-0000`

## [PLAW-09] Documentation Standards
> Every public API carries machine-parseable documentation in the stack's native convention, and comments explain why, not what.
Body: `rules/documentation.md` · Records: `ADR-0000`

## [PLAW-10] Dependency Management and Allowlist
> Only technologies on the project allowlist are permitted; any exception is documented through an ADR and approved by Architecture.
Body: `rules/dependencies.md` · Records: `ADR-0000`

## [PLAW-11] Branching Strategy & Version Control
> Every code change follows the declared branching model: no direct commits to protected branches, merges arrive through reviewed pull requests, versions are tagged by semantic rules.
Body: `rules/branching.md` · Records: `ADR-0000`

## [PLAW-12] Deployment & Environment Strategy
> Every deployment passes through the declared quality gates of its environment; production deploys require manual approval, and infrastructure changes are made only as code.
Body: `rules/ci-cd.md` · Records: `ADR-0000`

## [PLAW-13] QA Per-Increment Alignment
> Under incremental slicing, verification is per slice: each increment is closed by its own triple gate and QA report, and the plan-level status is derived, never written by hand.
Body: `rules/testing.md` · Records: `ADR-0000`
