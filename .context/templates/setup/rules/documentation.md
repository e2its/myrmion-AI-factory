# Documentation Standards

> **Auto-generated from** `docs/setup.md` decisions

## [PLAW-09] Documentation Standards
> Every public API carries machine-parseable documentation in the stack's native convention, and comments explain why, not what.

> **Mandate:** All public APIs MUST have machine-parseable documentation (docstrings).

### Language-Specific Standards
- **Python:** Google Style Docstrings (Args, Returns, Raises).
- **JavaScript/TypeScript:** TSDoc (@param, @returns, @throws).
- **Java:** Javadoc (@param, @return, @throws).
- **C#:** XML Comments (`<summary>`, `<param>`, `<returns>`).
- **Go:** Godoc format (comment above declaration).

### Minimum Requirements
1. **Description:** What it does (1-2 lines, imperative mood).
2. **Parameters:** Type, purpose, constraints.
3. **Returns:** Type and meaning.
4. **Exceptions:** When and why thrown.
5. **Example (Optional):** Executable snippet.

### Architecture Docs
- **C4 Diagrams:** Mermaid in `docs/spec/{FEATURE_ID}/design.md`.
- **ADRs:** `docs/project_log/adr/ADR-NNNN-title.md` for architectural decisions.
- **README per Module:** Purpose, dependencies, how to run tests.

### Comment Policy
- **Write WHY, not WHAT:** Good: `// Retry 3x due to API flakiness`. Bad: `// Call API`.
- **Debt Tracking:** `TODO:` for improvements, `FIXME:` for hacks (+ ticket ID).

## [LAW-06] Traceability
> Every generated artefact names the phase and the feature that produced it.

Every generated file opens with the traceability header in the stack's comment syntax: `// Generated by Phase: [ROLE] | Feature: [ID]` (e.g. `# Generated by Phase: IMPLEMENT | Feature: FEAT-012`). Artefacts carry their feature id in frontmatter. The header is how a reader, a sweep and the measurement reader join code to the phase and the feature that produced it.

## Deliverable homes (EVOL-080)

`config/quality.json → documents.homes` names one home per asked category: `Repo` or `External` (the store SETUP answered, Q38). With `adapter: none`, everything below is n/a.

| Category | Artefacts | Approved by |
| --- | --- | --- |
| `business` | `docs/spec/*/user_journey.md`, `docs/spec/*/slice_map.md`, `docs/ux/vision/vision.md`, `docs/ux/vision/navigation_map.md` | CODESIGN |
| `design` | `docs/spec/*/design.md`, `docs/spec/*/test_plan.md`, `docs/spec/*/devops_plan.md`, `docs/spec/*/fdr/*.md` | BLUEPRINT, DEVOPS |
| `report` | `docs/spec/*/qa/qa_report*.md`, `docs/spec/*/review/*.md`, `docs/spec/*/smoke_e2e_report*.md`, `docs/technical_due.md`, `docs/software_audit.md` | QA, IMPLEMENT review, AUDIT |

Everything the code compiles, runs or machine-reads stays in the repo: Gherkin, contracts, tests, config and the mock. So do the plans and records that delivery state moves.

With an `External` home:
- **Approve.** The step that writes the artefact approved then runs `python3 scripts/gate.py documents --approve <path>`. It publishes the bytes as a new version when they differ, writes `<path>.pin.json {source, id, version, approved_at, sha256}`, and removes the file. Commit the pin.
- **Read.** Read a pinned artefact with `python3 scripts/gate.py documents --read <path>`. You get the approved bytes at the pinned version, verified by hash. The store's latest version is never read. A file at the path is a draft, and it wins over the pin. Every existence or frontmatter check on the artefact counts the pin and reads through `--read`.
- **Refine.** A refine, or a cascade flip, on a pinned artefact first runs `python3 scripts/gate.py documents --pull <path>`. The pinned bytes come back as the draft, and the next approval re-pins.
- **Never** edit the page in the store outside approval. A version the pin does not name is drift: the `documents` gate turns red until the owner phase re-approves it, or the pinned version is restored in the store.
- **Store down.** The gate is n/a with a WARN. A direct `--read`, `--approve` or `--pull` exits 2: nothing rests on an unread source of truth. Wait, or fix the credential the message names. Never copy the artefact into the repo.
- **In CI.** With `documents.verify: ci` (Q38.8), the CI carries a read-only service-account credential. A missing one is a red wiring finding on every pull request once a category is homed outside the repo; a refused one when a pin is read. A pull request from a fork gets no CI secrets on most platforms: it stays red until a maintainer runs it. With `local`, the CI reports n/a with a WARN: the pins are verified on developers' machines only, a declared risk. A pull request that changes `verify` carries a WARN.
- **The store's address.** Under the gate profile, the credential goes only to the store the base names. A pull request that adds the store or changes where it points (Confluence's site, space, deployment; a built store's commands and credentials) reports n/a with a WARN until it merges. A store move is one pull request: `--pull` each pinned artefact at the old address, delete its pin, change the address, then `--approve` it at the new one.

## Template lookup

> Moved verbatim from `CLAUDE.md` § Generation Standards §1 (EVOL-064); `CLAUDE.md` keeps the rule in one sentence.

**Template lookup (on-demand, NOT session-start load).** Before creating any new artefact in a templated family (design doc, dev plan, test plan, ADR, QA report, peer review, security audit, user journey, blockers report, etc.), read the canonical template first and copy its frontmatter + section structure. Never invent schemas or copy from sibling documents (siblings inherit drift). Template locations by command persona:

| Command / persona | Template root |
| --- | --- |
| **CODESIGN** (PO ↔ UX) | `.context/templates/{po,codesign}/*.md` + `.context/templates/codesign/*.html` (mocks/shell) |
| **BLUEPRINT** (ARCH ↔ QA) | `.context/templates/architect/*.md` (design, ADR, technical gaps) + `.context/templates/qa/test_plan_template.md` |
| **IMPLEMENT** (DEV ↔ REVIEW ↔ SEC) | `.context/templates/develop/*.md` (dev plan, api/e2e/page object tests, blockers report) + `.context/templates/peer_review/review_template.md` + `.context/templates/security/{remedy,sec_audit}_template.md` |
| **QA** | `.context/templates/qa/qa_report_template.md` + `.context/templates/qa/test_gaps_proposals.md` + `.context/templates/qa/smoke_e2e_report_template.md` |
| **AUDIT** | `.context/templates/security/sec_audit_template.md` |
| **DEVOPS** | Embedded inside `.claude/instructions/Factory-devops-*.instructions.md` (search `## ... Template` sections) — no dedicated templates dir |
| **SETUP** | The whole `.context/templates/setup/**/*.md` tree (constitution, rules, ADRs, snippets, workflows, policies) — materialised by `SETUP --generate` |

These files are **on-demand**: read them when you are about to generate the matching artefact, never at session start.
